# Garden portraits

The portraits are generated by the released MiniT2I-L/16 checkpoint on the DGX
Spark, then saved as static WebP files in `birds/portraits/`. Viewing the website
does not start inference. The Raspberry Pi continues running BirdNET and sending
detections; it does not run the image model.

Runtime: `/home/nimitz/projects/bird-painter` on SSH host `nimitz`.

## Model and environment

- Model: [MiniT2I/MiniT2I](https://huggingface.co/MiniT2I/MiniT2I), L/16,
  revision `5b4da2870d1554992670d1005567e9d55b1b37bb`.
- Text encoder: `google/flan-t5-large`, revision
  `0613663d0d48ea86ba8cb3d7a44f0f65dc596a2a`.
- `pipeline.py` is the upstream implementation from the pinned model revision;
  its MIT license is included. No Python code is downloaded during inference.
- The installed Spark environment is recorded in `requirements-lock.txt`.
  This includes the ARM64 CUDA build of PyTorch, not a CPU-only environment.
- 512 by 512 pixels, 100 sampling steps, guidance 6, BF16 image model and FP32
  text encoder. Model weights are safetensors and were SHA-256 verified at setup.
- This is checkpoint inference. No bird-specific training has been performed.

The published collection contains 56 selected portraits. Generation on this
Spark took about 20 seconds per image, with 3.46 GiB peak PyTorch GPU allocation.
Prompts and seeds were revised for the weaker results; the illustrations still
have species-level inaccuracies and are not substitutes for identification photos.

The installed runtime has `checkpoints/minit2i-l-16/transformer/`,
`checkpoints/minit2i-l-16/scheduler/`, and `text-encoder/`. Weights and environments
are not stored in Git. On GB10, the runner initializes CUDA before model loading
and releases only its own model files' cached pages to avoid an observed startup
allocation failure. Other services on the Spark are not stopped or reconfigured.

## Generate or revise portraits

Copy `generate.py`, `pipeline.py`, and a prompt batch to the runtime directory,
then run there:

```sh
.venv/bin/python generate.py prompts.json --output collection
```

A batch is a JSON array with `id`, `seed`, and `prompt` for every image.
`portraits.json` records the selected images' complete prompts, seeds, model
revisions, timing, and output hashes. It can also be used as a prompt batch.
Existing completed PNGs are skipped; use a new ID for a revised prompt or seed.
The process exits after its batch and releases GPU memory. No public image
generation endpoint or background generation service is installed.

Review new images before publishing: this compact model can invent colors and
field marks. The site identifies them as AI illustrations and links to Cornell
for identification photographs. New birds still appear in the collection even
when their portrait has not been added.

After selecting a PNG, encode it as WebP at quality 90, add its entry to
`birds/portraits.js`, and record the generation metadata in `portraits.json`.
Keep collection numbers stable when adding species. The web assets and manifest
publish with the normal GitHub Pages deployment. Jekyll excludes this underscore
directory from the public site.
